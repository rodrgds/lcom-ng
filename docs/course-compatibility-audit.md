# Course compatibility audit

This reference tells instructors which LC exercises and device contracts lcom-ng can execute, which need explicit build inputs, and which require the Minix VM or physical hardware. It covers all 26 lesson files under `resumos/src/content/lessons/lc` and the four C files imported by those lessons. The local material identifies 2025/26 as its teaching basis. The supplied Ninjix repository also contains the FEUP Minix 3.4.0 SDK and 2026 lab sources. This audit does not establish the unpublished 2026/27 syllabus.

## Evidence and boundaries

The audit compares the curriculum with `sdk/compat/include`, `sdk/compat/src`, the device owners in `runtime/devices`, original student programs, and public device specifications. The compatibility corpus reports contain pinned repository revisions and unchanged-source hashes. A build success alone does not prove a correct student implementation.

The current Moodle course requires access unavailable to this audit. SIGARRA returned HTTP 403. The old `web.fe.up.pt` course URL was inaccessible through the browser tool. Accessible archived FEUP pages and the SDK bundled by students provide historical contracts, not a claim that current private handouts were downloaded. These are source-access limitations, not runtime failures.

## Corrections established by this audit

The FEUP SDK snapshot identifies Minix 3.4.0. Its endpoint arithmetic gives `ANY=31744`, `NONE=31743`, `SELF=31742`, `HARDWARE=-1`, `SYSTEM=-2` and `CLOCK=-3`. The earlier shim values were wrong. `SYS_PRIV_ADD_MEM` is 6. Notification IPC status is the masked call number `NOTIFY=4`; it differs from the message type `NOTIFY_MESSAGE=0x1000`. Public client checks fail with the old values and pass with the corrected header and implementation. The umbrella's conditional `MIN` and `MAX` macros also follow that SDK, including their repeated evaluation of a selected expression. [Minix endpoint header](https://raw.githubusercontent.com/Stichting-MINIX-Research-Foundation/minix/v3.3.0/minix/include/minix/endpoint.h), [IPC constants](https://raw.githubusercontent.com/Stichting-MINIX-Research-Foundation/minix/v3.3.0/minix/include/minix/ipcconst.h), [kernel notification implementation](https://raw.githubusercontent.com/Stichting-MINIX-Research-Foundation/minix/master/minix/kernel/proc.c), [current sys/param.h](https://raw.githubusercontent.com/Stichting-MINIX-Research-Foundation/minix/master/sys/sys/param.h).

Intel specifies that a count latch freezes the count until the required bytes have been read, repeated latches are ignored while one is pending, and readback with both selections returns status before count. Read and write byte sequences are independent. NullCount remains set until the new count transfers into the counting element. Mode 0 raises OUT once at terminal count and does not generate periodic IRQs. The new regression fails 15 checks against the old PIT and passes after the owner correction. The client one-shot check also fails against the old server and passes through both corrected transports. [Intel 8254 datasheet](https://www.cs.cmu.edu/~410/doc/8254.pdf).

RTC register behavior follows the compatible PC RTC contract, including BCD/binary data, alarm don't-care bytes, SET buffering, enable bits and read-clear register C. Faster-than-quantum interrupt coalescing remains explicit. [DS12885/DS12C887 RTC specification](https://www.analog.com/media/en/technical-documentation/data-sheets/ds12885-ds12c887a.pdf).

## Original lab evidence

Peucastro `lcom`, revision `f8fd47bcfdd76c5eb4e94e5e929e63a888259b2b`, supplies 15 successful unchanged-source runs: three timer, three keyboard, four mouse and five video callbacks. The machine-readable inventory has the exact per-run list and hashes in `build/compat-expanded/lab-evidence/builds.json` and `runs.json`. The mouse gesture receives a left-button rise and right-button fall, and the remote callback receives ACK plus three response bytes for every read. Pixel expectations are independent of the student renderer.

Adriano's RTC lab, revision `e0b46670ed2122e2ad303a7d5ed83e51b517d215`, omits keyboard declarations and its dependency from its lab6 build. Explicit ignored build inputs restore those missing dependencies without changing its C files. `rtc_test_date` prints the seeded 13/10/26 date. `rtc_test_int` receives actual IRQ8 notifications and raw register C `0xd0`, but the student's generic read function converts C as BCD to `0x82`, loses UF, and prints a zero date. This is partial original-source evidence, not a successful complete RTC IRQ application.

Bernardo's pre-LCF lab7, revision `14a410320637918a4b3df90177c5d319802da501`, needs `--cc "clang -include lcom/compat.h"` because its queue calls allocation functions without declarations. `conf 1` and `set 1 8 1 none 9600` exit successfully. The repeatable `tests/compat-serial-labs.json` gate verifies output and the ordered writes for DLAB, DLL=12 and DLM=0. Its displayed 49664 default bitrate truncates 115200 in the student's unsigned short. Its setter leaves DLAB enabled. Neither issue proves full TX/RX application correctness. Its lab6 has a missing nonstandard `-lvt` dependency and unimplemented interrupt callback, so it is not a positive RTC case.

The supplied Ninjix Lab 1 calls `freopen("/dev/console", "w", stdout)`. Main now forwards that output to the runtime's captured stdout, and a dedicated console test owns the output check. Its original program passes all 20 assertions and prints its success message. The lesson's pure bitwise/RTC source needs no generated callbacks.

LCF output logging now captures complete stdout through a pipe tee while retaining console output. Its regression covers direct writes, all standard print entry points, native helpers, reconfiguration, missing parents, `/dev/console`, normal exit and asynchronous file errors in single and paired runtimes. The unchanged Peucastro timer program produces the same two elapsed-second messages in both its requested log file and the runtime console. `lcf_trace_calls` remains unavailable; the supplied SDK requires wrapped invocations and `ctx_t` source metadata, and no original tracing implementation was supplied. It returns `ENOSYS` and creates no fake trace.

## Remaining work, ranked

1. Keep I8042 IBF busy intervals marked unmodeled unless a current lab requires them. Deterministic PARITY/TIMEOUT replay now covers the demonstrated fault recovery branch.
2. Keep UART physical framing, parity/break faults and THRE/TEMT timing marked partial. Trigger/timeout fixes should remain in the UART owner's focused single/pair regressions.
3. Keep PIT GATE-dependent modes, sub-tick timing, RTC high-rate coalescing and video vblank outside claims of physical equivalence. Existing virtual quanta suffice for the demonstrated lab callbacks.
4. Confirm current private handout/API changes with an authorized copy. Public archives and Resumos establish the listed teaching contracts, not unpublished assessment behavior.

The notes say reprogramming PIT0 can disturb the Minix system clock. Kernel clock source alone does not establish the FEUP VM's exact PIT/APIC routing. lcom-ng currently expresses system delays in 60 Hz units while RTC time follows elapsed virtual time. This audit leaves that comparison unresolved rather than changing the clock model from an unverified hardware assumption.

The C language reference, [N1570](https://www.open-std.org/jtc1/sc22/wg14/www/docs/n1570.pdf), and [OSTEP](https://pages.cs.wisc.edu/~remzi/OSTEP/) support the theory explanations. They do not specify FEUP's LCF dispatcher or the runtime's device register contracts.
